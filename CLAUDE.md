# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
cargo build --release      # also runs build.rs codegen
cargo test                 # ~188 tests across cigi, simulator, geo, orion, convert, config, platform
cargo run                  # TCP :8008 (Trillium), UDP cigi_listen_port (recv), UDP scene_generator_cigi_port (send)
cargo run -- --diag        # enable 1 Hz diagnostics log
cargo test <test_name>     # run a single test by name, e.g. cargo test slew_toward_target
```

To inspect generated Orion types:
```bash
cargo build && cat target/debug/build/cigi_trillium-*/out/orion_generated.rs | less
```

## Architecture

**Role: Trillium→CIGI bridge.** Receives Orion commands from a Trillium controller over TCP, converts them to CIGI, and drives a CIGI scene generator. `GimbalSimulator` is a fallback when the scene generator is unreachable (no `StartOfFrame` within 2 s).

**Data flow:**
```
Trillium Controller ↕ TCP (Orion big-endian) :8008
                    ↓
              [This App]  ← 50 Hz tokio::select! loop in main.rs
                    ↓
     ↕ UDP CIGI (little-endian) → scene_generator_ip:scene_generator_cigi_port
                    ↓
          CIGI Scene Generator (IG)
```

**Dual-path runtime:** The 50 Hz loop in `main.rs` checks `last_sof` to decide the path each tick:
- **Scene generator connected** → converts Orion commands to CIGI packets (`IgControl` + `EntityControl` + `SensorControl`) and sends them via UDP. Tracks IG frame counter and populates host timestamps.
- **Simulator fallback** → feeds commands into `GimbalSimulator`, which runs physics locally and produces synthetic telemetry at 10 Hz (every 5th tick).

**Channel architecture** (4 mpsc channels + 1 watch):
- `orion_cmd_tx/rx` — Orion commands from Trillium TCP server → main loop
- `orion_telem_tx/rx` — telemetry from main loop → Trillium TCP server
- `cigi_send_tx/rx` — CIGI datagrams from main loop → UDP host task
- `cigi_resp_tx/rx` — CIGI responses (SOF, SensorResponse) from UDP host → main loop
- `platform_tx/rx` — `watch` channel for `PlatformState`, driven by the configured source

**Platform sources** (`src/platform/`): Pluggable via `platform_source` config key. Trait `PlatformSource` defines the interface; implementations: `StaticSource` (default, from config), `MavLinkSource` (UDP MAVLink), `Stanag4586Source` (UDP multicast STANAG 4586).

### Key modules

- `src/main.rs` — 50 Hz Tokio loop; dual-path logic; channel wiring; IG frame counter tracking
- `src/simulator/mod.rs` — GimbalSimulator: all physics, modes, telemetry, laser rangefinder
- `src/geo.rs` — WGS84 geolocation (ECEF, NED, ray-cast, inverse geopoint, refraction)
- `src/config.rs` — Config struct; `config.toml` key=value parser (no deps); per-camera FOV table
- `src/faults.rs` — FaultState (GPS, motor, IMU, thermal, degraded GPS, encoder, laser), diagnostics
- `src/trillium/server.rs` — TCP server; accepts Orion connections
- `src/cigi/host.rs` — UDP CIGI host I/O; `CigiResponse` enum; datagram builder/parser
- `src/cigi/messages.rs` — CIGI v3.3 structs (hand-written per ICD)
- `src/platform/` — PlatformState + source trait + three implementations
- `src/convert/to_cigi.rs` — OrionCmd/PlatformState → IgControl/EntityControl/SensorControl
- `src/convert/to_orion.rs` — SensorExtendedResponse → GeolocateTelemetryCorePacket
- `src/orion/` — Re-exports types generated by `build.rs` from `OrionPublicProtocol.xml`
- `src/orion/wire.rs` — Orion framing: sync bytes (0xD0, 0x0D), Fletcher-16 checksum

## Key Patterns

**Preferred constructor:** `GimbalSimulator::with_config(cfg)` — not `Default`.

**Endianness:** CIGI packets are **little-endian**. Orion TCP wire protocol is **big-endian**.

**Codegen:** `build.rs` parses `OrionPublicProtocol.xml` at compile time → `$OUT_DIR/orion_generated.rs`. Never hand-edit Orion types; modify the XML or build.rs instead.

**Config loading:** `config.toml` in the working directory is loaded at startup. Missing file → built-in defaults. Section headers are cosmetic; only `key = value` lines matter. Unknown keys are silently ignored.

**Minimal deps:** Only `tokio` (runtime) and `roxmltree` (build-time XML parsing). No serde, no external CIGI/protocol crates.

**Zoom curve:** FOV interpolation uses an exponential (logarithmic focal-length) curve: `fov = fov_wide * (fov_narrow / fov_wide).powf(zoom_level)`. Not linear.

**Coordinated geopoint slew:** In geopoint mode, pan/tilt axes are coordinated to arrive simultaneously. The slower axis sets the pace; the faster axis rate is reduced proportionally.

## Gotchas

**`GimbalSimulator::tick()` takes `f64`** (not `f32`). Use a `f64` constant for DT.

**`GeolocateTelemetryCorePacket` field types:** `pan/tilt: f32` (radians), `pos_lat/pos_lon: f64` (radians), `pos_alt: f64` (metres).

**Scene generator detection:** "connected" = `StartOfFrame` received within last 2 seconds. No SOF → simulator fallback activates automatically.

**`SensorControl::decode` is test-only** (`#[cfg(test)]`). The bridge sends SensorControl (encode), never receives it.

**Trapezoidal deceleration:** The decel branch condition is `stop_dist >= err.abs()` where `stop_dist = v²/(2a)`. Do NOT add an extra `max_accel * dt * dt * 0.5` term — it causes zero-velocity startup to skip to the decelerate branch.

**SensorControl field mapping** (non-obvious CIGI extension):
- `sensor_state` 4 → Geopoint mode (not in base CIGI v3.3 spec); uses bit 2, overlapping polarity flag
- `track_mode` bit 0 → Rate vs Position when `sensor_state=1`
- `sensor_id` → camera index (0=EO wide, 1=EO narrow, 2=IR); forwarded to scene generator
- `ac_coupling` → zoom level (Position/Rate) or geopoint lat (Geopoint); forwarded to scene generator
- `noise` → geopoint lon fraction (Geopoint mode only)

**CIGI gate_x_pos/gate_y_pos:** These fields carry the image-plane tracking gate centroid position (CIGI v3.3 spec-compliant), NOT gimbal pan/tilt angles. In track mode they equal `track_target[0]/[1]`; in all other modes they are 0.0 (bore-sighted). Pan/tilt are only available via the Orion TCP telemetry path.

**Camera switch blackout:** `entity_lat/lon/alt` returns 0,0,0 for 200 ms (10 frames at 20 Hz) after a camera switch. Tests must account for this.

**Continuous pan:** `pan_limit_deg = 360` enables unlimited rotation. Shortest-path algorithm is used; reported angle wraps to (−180°, 180°].

**Sensor status mapping:**
- Position/Geopoint settled (error < 0.01 rad) → 0 (Locked)
- Position/Geopoint slewing → 2 (Slewing)
- Rate mode → 2 (Slewing)
- Track active → 1 (Tracking)
- Track lost / Disabled / Fault → 3 (Breaklock)

**`inverse_geopoint` does not account for platform roll/pitch** when `stabilization_quality > 0`. The forward LOS path applies full ZYX rotation, but the inverse only subtracts yaw. Geopoint mode will have residual pointing error proportional to `roll/pitch * stabilization_quality`.

**GPS fault packet uses `FaultTypeNone`** — the Orion protocol XML defines no GPS-specific fault type. `FaultTypeNone + FaultLevelWarning` is the convention. Update if a GPS fault type is added to the XML.

**Track loss triggers:** Two independent conditions cause track loss: (1) target offset exceeds `track_loss_threshold` fraction of FOV, or (2) computed confidence drops below 0.3 (target too small or too far from center).

**Thermal throttling:** When `thermal_warning` fault is active, effective `max_slew_rate` is reduced by 50%.
